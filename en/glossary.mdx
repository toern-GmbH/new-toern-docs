This glossary explains all terms that matter in the return process with toern. It's continuously extended. Missing a term? Write to us at [support@re-toern.de](mailto:support@re-toern.de).

## A

**Admin API Key**  
Security token (e.g. Shopify "shpat…") that gives toern read and write access to your Shopify shop system. See [Shopify integration](/en/getting-started/shopify-integration).

## B

**Brand**  
The company or online retailer that uses toern for its returns management.

## C

**Carriers (CEP providers)**  
Courier, express and parcel services (e.g. DHL, DPD, GLS) that handle the return shipping. Usually toern is connected to them via an interface and creates return labels automatically.

**Claim**  
Report of a defective item. Often combined with photo uploads (User Inputs) and brand-specific processes to settle the refund. See [Claim portal](/en/claims/claim-portal).

**Clarification cases**  
Returns with the status "needs review" that have to be checked manually, e.g. due to technical errors, blocked discount codes or defective goods. See [Clarification cases and how to solve them](/en/faq).

**Classification**  
The quality check and condition rating of returned items (e.g. by fulfillment). It's often a prerequisite for the refund. toern uses the classifications A, B, C and D.

**Collections**  
Groups of return reason sets. You can assign them globally or to specific product types. See [Return reasons](/en/returns/return-reasons).

**Country mapping**  
Central setting that defines from which countries returns are allowed and which shipping rules apply there. See [Return methods](/en/returns/return-methods).

**Cover image**  
A customizable image on the portal's login page. It visually supports your branding. See [Branding](/en/branding/general).

**Customer KPIs**  
The "traffic light rating" (Return Rate, Monetary Metric) that helps you assess a customer's return behavior. It's shown in the customer data of every return.

**Customer support**  
Your brand's team that reviews returns and handles tickets created by toern-AI in the dashboard.

**Customer Tickets**  
Cases created by toern-AI that prioritize critical customer feedback by urgency. See [Customer Tickets](/en/dashboard/customer-tickets).

## D

**Dashboard**  
The central admin interface for brands. This is where you manage returns, analytics and system settings.

**Discounts**  
Discounts of the original order. They're taken into account proportionally when calculating the refund amount.

## E

**Events**  
Technical events (e.g. ReturnRegistered) that toern sends to third-party systems such as Klaviyo to trigger email flows.

**Exchanges**  
The process of directly replacing a returned item with the same item in a different variant. In toern this is covered by the "Exchange" feature: customers swap items directly for other variants (size/color). See [Exchange](/en/returns/exchange).

## F

**Fulfiller**  
Logistics partners that physically handle incoming returns and send status updates (received/inspected) to toern. See [Fulfillment integration](/en/fulfillment/fulfillment-integration).

## G

**Gift cards**  
Optional refund type. Gift cards keep revenue in your shop, e.g. through vouchers or waived fees. See [Gift card refund](/en/returns/gift-card-refund).

**Guideflows**  
Interactive, embedded click-through guides. They help you configure and understand complex features.

## I

**Interface**  
Technical API connection for exchanging data between toern and third-party systems such as ERPs (Xentral) or logistics providers.

**Item**  
The physical products of an order. Customers can select them individually for return in the portal.

**Item level**  
Detailed view of data where each item of an order is analyzed individually.

**Item variants**  
Specific versions of a product (e.g. size or color). They matter for the real-time stock check during exchanges.

## K

**Klaviyo**  
Marketing tool integration that triggers automated emails based on return events (e.g. ReturnRegistered). See [Klaviyo](/en/integrations/klaviyo).

## L

**Label Fee**  
A fee for creating and using the shipping label. You set it in the return settings.

## M

**Manual refunds**  
Credits or payments triggered by hand in the dashboard. You need them when there's a clarification case and the refund doesn't run automatically.

**Manual returns**  
Returns that support staff create for customers directly in the dashboard, e.g. when the return window has expired. See [Manage returns](/en/dashboard/manage-returns).

**Marketplaces**  
External sales platforms (e.g. Avocadostore). Their returns can also be identified via the postal code login in the portal.

## N

**Notes**  
Internal communication feature within a return. It supports @-mentions and file attachments.

## O

**Onboarding**  
The guided process for the technical connection (API setup, carrier integration) and configuration of a new brand in toern. It starts with a kick-off meeting, followed by the technical integration, the showcasing and finally the go-live.

**Order number**  
The unique identification number of an order. Customers need it to log in to the return portal.

## P

**Parcel level**  
Display or calculation of metrics (e.g. return rate) based on the whole shipment rather than individual items.

**Payment method**  
The payment method the customer used for the purchase. With a standard refund, the money is paid back through it.

**Product bundles**  
Sets of several items. In the return process they're handled as one unit or as individual parts (depending on Shopify apps). Both terms, set and bundle, are common. See [Sets](/en/returns/sets).

## R

**Refund method**  
The chosen form of repayment, e.g. via the original payment gateway or as a gift card. See [Refund](/en/returns/refund).

**Retention Rate**  
Metric in the overview dashboard. It measures the share of revenue retained through exchanges and gift cards. See [Analytics](/en/dashboard/analytics).

**Return**  
The sending back of items from an order placed with an online retailer (brand). A return includes one or more items and can be registered digitally via toern. It describes the physical or digital process of a customer sending items back.

**Return confirmation**  
The last step in the portal, where the customer bindingly submits their selection.

**Return details**  
Detail view of a single return in the dashboard, with information and analyses on items, classification and refund receipts.

**Return Fee**  
General, configurable fee per return, independent of the label. It can be deducted automatically from the refund amount and applies in addition to or instead of the Label Fee.

**Return policy**  
Your brand's legal set of rules. It's linked in the portal and defines the conditions for refunds.

**Return portal**  
The customer-facing self-service web interface for registering returns and exchanges. See [Return portal](/en/returns/return-portal).

**Return process**  
The structured flow of a return: from the login in the portal through the physical shipment to the final refund and completion in the backend.

**Return rate**  
Metric in the overview dashboard. It describes the ratio of returns to orders in a given period.

**Return reasons**  
Reasons for returning an item (e.g. "Too big") that customers must choose in the portal. They're synced with Shopify or Xentral via mappings, are used for analytics and can be set up as collections in the settings. See [Return reasons](/en/returns/return-reasons).

**Return Shipment Status**  
Status display in the dashboard. It shows the physical journey of the shipment (e.g. Transit, Delivered).

**Return Slip**  
The return slip the customer puts in the parcel. It lets you match the return when **no** label is used.

**Return status**  
The current processing state of a return in the system (e.g. registered, received, on hold, inspected, refunded or clarification).

**Return window**  
The defined, configurable period (including buffer time) after receipt of the goods during which a return is allowed. See [Return settings](/en/returns/return-settings).

**Roles**  
Permission system in the dashboard. It distinguishes between "Brand admin" (all rights) and "Support user" (operational focus). See [User management](/en/dashboard/user-management).

## S

**Shop**  
A brand's e-commerce instance where customers buy the goods. A shop can run on different shop systems, which are usually connected to toern.

**Shop locations**  
Warehouse locations stored in Shopify. They're used for the stock check during exchanges.

**Shop system**  
The backend of your brand's shop (mainly Shopify). It provides the order data and receives refunds. WooCommerce or JTL can be connected as well.

**Showcasing**  
The step in the toern onboarding that shows how customers use toern. The showcasing consists of several guideflows covering all current toern features and processes.

**Stock**  
The inventory in the shop. toern can automatically increase it again after a successful return.

## T

**Third-party services**  
External tools and platforms (e.g. Klaviyo, Xentral, Zendesk, Quivo) that you can connect to toern via interfaces.

**Ticket System**  
Tickets that toern-AI creates from customer inputs. If toern-AI detects that an input on a return requires action, a ticket is created automatically.

**toern-AI**  
The artificial intelligence of the toern platform. It analyzes inputs, assigns tags and creates recommended actions for tickets.

**ToernBot**  
Special system user. When you tag it, it informs toern's technical support about problems.

**Toggle button**  
Switch in the settings that lets you quickly enable features such as "Automatic Refund" or "Enable Exchange".

## U

**User Inputs**  
Additional customer feedback during the return process, as free text, photos or voice messages.

## X

**Xentral**  
ERP integration. See [Xentral](/en/integrations/xentral).

## Z

**Zendesk**  
Support integration. It shows return data directly in the customer ticket and syncs AI tickets. See [Zendesk](/en/integrations/zendesk).
