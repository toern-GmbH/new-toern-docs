To let your customers send their returns back easily, toern ideally creates shipping labels automatically. To do this, you connect your dashboard directly to your shipping provider. Alternatively, you can work without an integrated shipping service. In that case, your customers send the return themselves to an address you define.

## Supported shipping providers

toern offers native integrations for the most common carriers. Choose the provider you have an active contract with:

1. **DHL**
2. **DPD Web Connect**
3. **GLS Shop Returns**
4. **PostNord Return Drop Off**
5. **Quivo Logistics**: If Quivo is your fulfiller, toern uses the Quivo Shipping API directly. This speeds up the setup considerably.
6. **Exporto**: For cross-border returns, e.g. from Switzerland and the UK.
7. **Post AT**: Austrian Post, for returns to Austria.
8. **Sendcloud**: Return labels through your own Sendcloud account, using the carriers enabled there (currently for returns within the EU).

Under **Settings → Return Shipping Service**, you choose between the available shipping providers and can switch between them at any time.

![Selecting the shipping provider](/images/docs/DHL/ShippingNew01.png)

<Warning>
  Before toern can generate the first label, an active integration is required. Without your credentials (e.g. the EKP number for DHL or API credentials), toern can't transmit shipping data to the provider.
</Warning>

## Return methods

Return methods define how your customers send their items back. You create them per country under **Settings → Return → Return Methods**. A country can have several methods, even several of the same carrier. Your customers then choose one of them in the portal.

Each method has one of the following types:

1. **Carrier**: toern creates the label automatically through one of your integrated shipping providers.
2. **Self ship**: Your customers ship the return themselves to an address you define.
3. **In store**: Your customers bring the items to one of your stores. No shipping is needed.
4. **Brand Upload**: You upload a label for each return yourself on the return detail page. toern then emails it to your customer.

### Fees

Every method has two fees:

**Label fee**: A fee you deduct from your customers for the label. This lets you pass on your label costs.

**Return fee**: A fee you deduct from your customers for the return itself, because it causes costs for you. It's independent of the label.

Both fees together are the total return fee of the method. That total is deducted from the refund amount. Always enter fees in euros, no matter which country. Enter `0` to offer the method for free.

### Flows

toern has three flows: regular **Returns**, **Claims** and **Withdrawals**. Under **Available in**, you choose in which of these flows a method is offered. By default, a new method is available in all three.

Turn a flow off if you want to handle it differently. For example, your DHL method for Germany could be offered only for returns, with a label fee. A second DHL method for Germany, offered only for claims, could then have no fees at all. Customers only ever see the methods of the flow they're in.

A method always needs at least one flow. To stop offering a method entirely, deactivate it with **Active** instead.

![Add return method](/images/docs/Settings/ReturnSettings04.png)

### Add a return method

1. Click **Add Return Method**.
2. Select the country and the type.
3. Under **Available in**, keep all flows or turn off the ones the method shouldn't be offered in.
4. Fill in the details for the type. For **Carrier**, select the shipping service. For **Self ship** and **In store**, enter an address, instructions, or both.
5. Enter a name and an optional description for each portal language.
6. Enter the label fee and the return fee.
7. Optionally add an image, availability rules or set the method as default.
8. Click **Add Return Method**.

<Warning>
  After adding a carrier method, always check under **Return Shipping Service** that a matching address exists for the carrier. If the country is missing at the carrier, no label can be created.
</Warning>

### Default method and availability rules

**Default option**: The default method is pre-selected in the portal. It's also used as a fallback if no other method matches the order's tag rules. There is one default per country and flow. If you set a new default that shares a flow with the current one, the current one stops being the default. The dialog tells you before you save.

**Availability rules**: You can limit a method based on the tags of the order. Either offer it only if the order has one of the tags, or block it if the order has one of them.

### European Union fallback

Select **European Union** as the country to create a method for all EU member states at once. An EU country uses these methods for a flow when it has no methods of its own for that flow. For example, if you only set up a claims method for France, French customers still get the EU methods for their regular returns.

### Return methods table

The table lists all your methods with their country, type, flows, fees, rules and status. A star marks the default method. The **Flows** column shows **All flows** or the flows the method is limited to.

Filter the table by type, flow and country, or search by name, country or carrier. Use the flow filter to check exactly which methods your customers see in a claim or a withdrawal.

## Return countries

**Return Countries** is a read-only overview of the countries you've set up return methods for. For each country, it shows per flow whether your customers can start a return, a claim or a withdrawal there:

1. **Number of methods**: Customers choose from these active methods.
2. **Via EU**: The country has no methods of its own for this flow, so customers get the European Union methods.
3. **Inactive**: All methods of the country for this flow are deactivated.
4. **Not offered**: No method of the country is offered for this flow.

![Return countries](/images/docs/Settings/ReturnNew02.png)

If a country shows **Inactive** or **Not offered** for a flow, customers from that country can't log in to that portal. They see a message that their country isn't supported. To change which countries are supported, add or edit return methods.

<Note>
  Withdrawals also need the country to be enabled under [Withdrawal Countries](/en/withdrawal/withdrawal-settings#withdrawal-countries).
</Note>

### Limitations

- A country is only supported for a flow if it has an active return method for that flow, or if it's an EU country and the European Union has one.
- For DHL and DPD, you also need to select or create the matching locations for each country in the settings.
- For Quivo, the corresponding countries must be configured in the Quivo settings.

## Fallback label sender address

The **Fallback Label Sender Address** is used when the shipping provider rejects your customer's address during label creation. toern then automatically retries the label creation with the fallback address you've set.

You can find the setting under **Settings → Return → Fallback Label Sender Address**.

![Fallback Label Sender Address settings](/images/docs/Settings/FallbackSenderAddress01.png)

The fallback address needs the following details:

1. **Company Name**: Company or fulfillment name
2. **Street**: Street
3. **House No.**: House number
4. **Zipcode**: Postal code
5. **City**: City
6. **Country**: Country, selected from the country dropdown

Changes are saved automatically. Fill in the address completely so toern can use it for the second label attempt.

Your customer's name stays on the return label. The company name you entered appears below it as a `c/o` line:

```text
Max Mustermann
c/o Muster Fulfillment GmbH
Musterstraße 10
12345 Musterstadt
Deutschland
```

If no complete fallback address is set or the second attempt fails too, no label can be created. In that case:

- Your customer receives an email about the failed label creation.
- If your brand has a primary support email, you receive this email in BCC at the same time.
- toern creates a clarification case for the return in **Manage Returns**.

## Label order identifier

toern can add a number to the return label that identifies the order. Which number works best depends on your fulfillment process. You can choose between:

- **Shopify Order ID** (default)
- **UUID** that toern assigns to every order
- **Shopify Order Number**: the order number you can customize, e.g. with letters

![Label order identifier](/images/docs/Settings/ReturnNew06.png)

## Return slip attachment

Some fulfillers need a return slip in the package for certain returns. This mainly applies to returns without an automatic label, where your customers only receive the destination address and ship the parcel themselves.

If the return slip is active, toern automatically attaches a PDF to the email your customers receive after registration with the information on the next steps. The PDF contains a QR code with the relevant information for your fulfiller. This way, the fulfiller's processes can be followed.

![Return slip](/images/docs/Settings/ReturnNew05.png)

For the QR code, you can use the **UUID** that toern generates for every order instead of the order number. You can also set the order number to be used if no UUID exists.

<Note>
  You can only enable return slips for returns where no label is created.
</Note>
